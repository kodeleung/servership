## Linux 环境验收

在可丢弃服务器中准备至少两台 Debian / Ubuntu、运行中的 systemd 和 SSH。分别配置 root、可 sudo 普通用户、无法 sudo 用户。初始登录密钥与项目新密钥应不同。

1. 批处理中让首台提权失败，验证未写公钥或安装，下一台仍成功。
2. 新生成密钥并验证公私钥匹配；分别测试带口令和 ssh-agent。
3. authorized_keys 准备现有公钥、不同 comment、无末尾换行，验证原内容保留、追加去重；用 stat 检查 700/600 和 UID/GID。
4. 验证符号链接/非法公钥被拒绝，且未修改链接指向文件。
5. 执行空软件选择：授权成功，未调用安装器。
6. 分别安装四个软件，核对真实版本、服务状态和安装结果；sing-box 无配置不启动，OpenSSH 既有配置及正在运行的进程不变。
7. 再执行一次，验证已满足状态、不升级、不重复追加公钥。
8. 模拟 apt 锁、网络失败和 Ctrl+C，验证结果与未执行项对应正确，临时目录清理；不删除 apt 锁。

## 实际验收结果

环境为本机 Orbstack 中的三个可丢弃 arm64 Linux 容器，使用真实 systemd 与 sshd：Ubuntu 24.04 两台、Debian 13 一台。初始环境没有 python3，项目服务端流程正常运行；安装器随后安装的软件依赖可能自行带入 Python，但项目不使用它。

- 完整客户端在真实终端运行：YAML → 两台服务器复选框 → 空软件选择 → 复用密钥 → root/sudo 授权 → 公钥登录 → 清理与汇总，退出 0。
- Ubuntu 多台实际 SSH：首台无 sudo 权限失败，后续 sudo 用户和 root 继续成功；第二次执行公钥不重复。目录/文件分别为 700/600，UID/GID 正确。
- 额外账号验证原文件保留、缺末尾换行、重复授权；authorized_keys 符号链接被拒绝，链接指向文件保持原内容。
- 本机真实终端生成带口令 Ed25519 密钥并提取公钥，口令不回显、不进入输出；临时 ssh-agent 解锁后实际服务器公钥登录成功。
- 新密钥验证：配置另一个有效 IdentityFile 并预建 ControlMaster 后，未授权的新密钥仍被拒绝。正确私钥旁放置错误但有效的 .pub 时仍能通过。原 ProxyJump 别名、路由和主机信任设置保留且实际登录成功。
- 真实 SSH PTY 中在安装器 sleep 阶段发送 Ctrl+C：返回 130，后续软件及第二台服务器未执行，已开始但未完成的项目被记录，临时目录清理。
- Ubuntu 24.04、Debian 13：Caddy 与 Docker 新安装成功，daemon 和服务均 active；sing-box 新安装成功，服务 inactive，临时 policy-rc.d 已移除；OpenSSH 既有服务验证后跳过。
- Ubuntu 再执行全部安装项均 skipped，保留配置、没有升级；单项下载失败时其他项目仍继续，汇总准确。
- 验证到 Caddy 2.11.7、Docker Engine 29.8.2、sing-box 1.14.2。这是本次测试版本，不是项目固定版本。
- Python wheel 构建成功，包含全部远程 Shell 模块。

sing-box 的官方密钥入口 `https://sing-box.app/gpg.key` 重定向到 `https://deb.sagernet.org/gpg.key`。前者在测试网络 TLS 握手失败，使用官方重定向目标后实际安装成功；安装器直接使用目标地址，并给下载设置超时。

未实际覆盖：amd64、Debian 12、Ubuntu 22.04/26.04、新安装 OpenSSH server（初始 SSH 已安装）。包管理锁冲突和软件服务失败通过受控边界测试验证，没有破坏真实环境来制造锁冲突。临时测试容器和项目专用镜像在验收后删除。

## 本次实施取舍

- 在空项目的新功能分支直接实施，没有创建第二份 checkout；影响仅是工作区组织方式。
- 工作流引用的辅助技能/脚本不在可用目录中，使用逐任务测试和执行记录替代；因此缺少这些辅助脚本自身的自动流程检查。
- 首版安装矩阵限定 Debian 12/13、Ubuntu 22.04/24.04/26.04 和 amd64/arm64；其他系统会被拒绝，便于先维护明确的支持范围。
- 已有 policy-rc.d 时拒绝新装 OpenSSH/sing-box，不覆盖用户策略；这类服务器需要先处理既有策略后重试。

独立整体代码审阅发现的新密钥验证、远程取消及部分结果丢失问题均补充失败测试后修正；其他身份、复用连接、错误 .pub 和 ProxyJump 的情况另做了实际 SSH 验证。
