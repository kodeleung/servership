# Servership 首版设计：电脑端执行与批量服务器

## 目标与范围

Servership 在用户自己的电脑上运行，通过 SSH 初始化一台或多台 Debian / Ubuntu 服务器，配置登录公钥并安装 Caddy、Docker、sing-box 和 OpenSSH。本机以当前用户运行，不要求 root；服务器在任何远程写入或安装前取得 root 权限。私钥在用户电脑生成和保管，不传输到服务器。

客户端使用 Python 实现，采用统一的软件选择和本机密钥，按清单顺序逐台执行、隔离失败，完成后汇总。服务器清单使用 YAML，服务器和软件均通过复选框选择。服务端通过系统 SSH 执行命令和小型 Shell 安装脚本，不要求安装 Python。

## 本机交互与服务器清单

1. 检查 Python 3.10 或更高版本、PyYAML、SSH、scp、ssh-keygen、gum 和交互终端。缺少依赖时显示安装指引并停止，不自动修改本机环境。兼容 macOS 与 Linux 本机；使用 PyYAML 安全加载和结构验证，不自行解析 YAML。
2. 读取 UTF-8 YAML 清单，默认文件为 servers.yaml，也允许指定路径。整份清单在任何远程操作前完成验证；错误指出服务器标识、字段或语法所在行。提供 servers.example.yaml 文档示例。
3. 展示服务器复选框，可选择全部或部分服务器；默认全不选。未选择任何服务器并确认时正常结束，不生成密钥、不连接服务器。Esc/Ctrl+C 则取消，返回 130。
4. 展示软件复选框：↑/↓ 移动，Space 勾选/取消，Ctrl+A 全选/取消全选，Enter 确认；默认全不选。一次选择应用于整批选中的服务器。空软件选择仍配置公钥，Esc/Ctrl+C 取消整个流程。
5. 选择复用本机密钥或创建 Ed25519 密钥，整批共用同一密钥。默认路径为 ~/.ssh/servership_ed25519；已有文件不得覆盖。口令由 ssh-keygen 原生交互处理；复用时从私钥提取并验证公钥，不盲信已有 .pub 文件。支持用户自己的 ssh-agent 减少重复输入口令，不修改长期 agent 配置。
6. 执行前显示选中的服务器、有效账号/端口及软件摘要。只有被选中的服务器进入后续步骤，并保持清单顺序。

### YAML 结构

```yaml
defaults:
  port: 22
  user: root

servers:
  - name: singapore-01
    host: 203.0.113.10

  - name: tokyo-01
    host: 203.0.113.20
    port: 2222
    user: ubuntu
    identity_file: ~/.ssh/existing_key

  - name: hongkong-01
    host: server.example.com
    user: debian
```

- 顶层包含可选 defaults 和必填 servers；servers 必须为非空列表，defaults 仅支持 port 和 user。
- name 和 host 必填且为非空字符串，name 在整份清单中唯一。host 支持域名、IPv4、IPv6，不允许选项前缀或控制字符。
- 每台 port、user 覆盖 defaults；两处均未提供时分别为 22、root。port 为 1–65535 的整数，user 为已有登录账号，不创建新账号。
- identity_file 可选，是首次登录使用的本机私钥路径。允许空格，展开当前本机用户的 ~，相对路径基于清单文件目录；检查文件存在且可读。未填写时不指定初始私钥，让标准 SSH 使用 ssh-agent、用户 SSH 配置或密码提示。
- 本次新建/复用的授权密钥在运行时统一选择，清单不记录其私钥内容；不存储服务器密码或 sudo 密码。
- 拒绝重复 YAML 键、未知字段、非法字段类型及自定义对象标签。使用成熟 YAML 解析库并进行结构验证，不执行清单中的表达式或代码。
- 整份清单（包括未选中的服务器）必须通过语法、字段、重复标识和初始身份路径验证，否则在远程连接前停止。
- 首次连接使用标准 SSH 主机密钥校验，不自动忽略检查。

## 每台服务器的执行流程

按清单顺序逐台执行，同一时刻只处理一台，SSH / sudo / 私钥口令提示明确关联服务器名称。

1. 使用该服务器的初始认证建立 SSH 连接，检查 Debian / Ubuntu、apt、systemd、发行版本和架构。
2. 验证服务器 root 权限。root 登录直接继续；普通登录用户通过 sudo 原生终端交互验证，检查确实能够运行所需 root 操作。提权失败则该服务器失败，不写入公钥、不安装软件。
3. 验证通过后才暂存执行模块和公钥。后续变更会话也需检查/重新取得 root 权限，不假定不同 SSH 会话共享 sudo 缓存。服务器密码、sudo 密码不通过命令参数或脚本输入通道传递，不记录到日志。
4. 将公钥添加到该服务器登录账号的 ~/.ssh/authorized_keys。通过账号数据库解析家目录与 UID/GID；保留原内容，以密钥类型与主体去重；.ssh 权限 700、authorized_keys 权限 600，归属目标登录账号。拒绝非法公钥、符号链接和涉及写入的非普通文件。
5. 使用新本机密钥验证该账号公钥登录成功。指定私钥和公钥认证，禁止回退服务器密码/键盘交互认证来掩盖失败，但允许私钥口令交互。验证失败则不安装软件，报告公钥已添加。
6. 公钥登录成功后使用该密钥执行安装，先重新验证该会话的 root/sudo 权限；按照统一软件选择调用独立安装器。
7. 清理项目创建的远程临时目录，记录密钥步骤和每个软件结果，然后处理下一台。

单台连接、提权、密钥配置失败只停止该台的后续步骤，继续其他服务器。单项软件安装失败继续该台其他独立软件。用户 Ctrl+C 则停止整批，尝试清理当前临时内容，并将未开始的服务器标记为未执行。

## 软件安装边界

- 采用各项目当前官方支持的安装来源、软件包和签名/校验机制。实施时核对发行版版本和 CPU 架构支持；不支持的组合在修改软件源前拒绝。
- Caddy：安装并验证服务状态，不配置站点或申请证书。
- Docker：安装官方 Engine、CLI、Compose 插件并验证 daemon，不将普通用户加入 docker 组。
- sing-box：安装并验证二进制版本，未配置节点时不启动服务，结果标注待配置。
- OpenSSH：安装服务器包并验证配置与服务，不改端口、密码登录、root 登录策略，不主动重启已有 SSH 服务。
- 既有有效安装跳过，不自动升级、卸载或覆盖。损坏/不兼容状态报告失败，不自动修复。保留已有配置。
- apt/dpkg 锁冲突报告失败，不强制删锁或终止其他包管理器。

## 结构、状态与结果

Python 客户端负责交互、清单、密钥、顺序批处理和汇总；调用系统 OpenSSH 的模块负责连接参数、提权、传输和清理；远程 Shell 模块负责系统检测、公钥写入、包管理和四个安装器。服务器仅使用 Bash、系统工具、apt 和 systemd，不要求 Python 或本机 YAML/界面依赖。客户端用 subprocess 参数列表且不使用 shell=True；远程命令参数统一安全引用，不使用 eval。

汇总按服务器展示：系统/提权、公钥配置、公钥登录、每项软件以及失败阶段。状态包括成功、已满足、失败、未执行。任意服务器或安装项失败则整体非零退出；全部成功或已满足则 0；用户取消则 130。整体结束后不会自动回滚已完成的授权或软件安装。

临时目录权限为 700，成功、失败和取消均执行清理，清理失败报告路径并保留原始错误。私钥不上传、不打印、不提供导出或下载操作，结果不包含任何密码。

## 验证与验收

- 真实终端验证复选框全部交互，特别是空选择与取消区别。
- YAML 清单验证多台、默认值/单台覆盖、重复键/标识、未知字段、类型、错误定位、IPv6、空格/相对身份路径和注入字符；非法清单无远程修改。
- 服务器复选框验证全部/部分/空选择和取消，未选中的服务器无连接，执行顺序与清单一致。
- 验证私钥不覆盖、不上传、不泄漏；本机权限归属当前用户。
- root 与 sudo 用户逐台验证，提权拒绝时无远程变更。
- 公钥追加保留内容、正确去重与权限；公钥登录验证无服务器密码回退。
- 两台以上服务器验证一台失败另一台继续、顺序提示、结果对应正确；取消后其余服务器未执行。
- 空软件选择仍为每台配置公钥，且不执行软件安装。
- Debian / Ubuntu 可丢弃 SSH/systemd 环境验证各安装器、重复运行、服务状态和配置保留。不在当前 macOS 主机执行 Linux 安装，不操作用户未指定的真实服务器。
- 没有可用 Linux 环境时，明确报告模拟测试和真实运行未验证的边界。
